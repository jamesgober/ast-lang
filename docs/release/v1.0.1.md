# ast-lang v1.0.1: shared and cyclic handles

**Documentation patch.** No change to the library code or its behaviour. The
public API is unchanged.

## Changed

### `walk` documents the tree assumption

`walk` visits the nodes reachable from a root, depth first, with its own heap
stack. It assumes those nodes form a tree, with one path from the root to each
node. The arena does not enforce that, and two ordinary patterns break it:

- A desugaring pass that reuses a child handle under two parents. `walk` then
  visits the shared subtree once per path to it, which grows exponentially when
  sharing nests.
- Back-patching through `Arena::get_mut` that stores an ancestor's handle in a
  descendant. `walk` then never ends, and its work stack keeps growing.

`transform` already documented that it assumes a tree. `walk` and `Visitor` now
say the same, in the rustdoc and in `docs/API.md`, and show the guard: keep a set
of handles already entered in the visitor and return `Flow::SkipChildren` for a
repeat. `Id` is `Ord` and `Hash`, so any set works, and every node is then
entered exactly once, even on a cycle.

A new doc example walks `x + x` with both operands the same handle, and a unit
test walks a real cycle built with `get_mut`; both terminate and enter each node
once.

## Upgrading
